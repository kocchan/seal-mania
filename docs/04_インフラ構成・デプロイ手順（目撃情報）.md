# インフラ構成・デプロイ運用マニュアル (ECS Fargate版)

## 1. インフラアーキテクチャ概要

本システムは、Dockerコンテナ技術とAWSのフルマネージドサービス（ECS Fargate / EventBridge）を組み合わせた**サーバーレス・バッチ処理アーキテクチャ**を採用しています。

```mermaid
graph TD
    %% 開発環境・CI/CD
    Local[ローカル開発環境<br>Docker build] -->|docker push| ECR[AWS ECR<br>コンテナレジストリ]

    %% AWS クラウド環境
    subgraph "AWS Cloud (ap-northeast-1)"
        Event[Amazon EventBridge<br>スケジュールトリガー]
        
        subgraph "Amazon ECS (Fargate Serverless Cluster)"
            Task[SealTask / latest<br>一時起動コンテナ]
        end
        
        Logs[CloudWatch Logs<br>実行ログ蓄積]
    end

    %% 外部サービス連携
    Event -->|指定時刻 (9:00, 12:00...)| Task
    ECR -.->|イメージPull| Task
    
    Task -->|スクレイピング| Yahoo[Yahoo!リアルタイム検索]
    Task -->|プロンプト送信| Gemini[Gemini API]
    Task -->|REST API (POST)| WP[WordPress / シールマニア]
    Task -->|標準出力ログ| Logs

```

### 💡 Fargate採用のメリット

* **完全自動スケーリング・保守不要:** EC2のようにOS（Ubuntu等）のパッチ当てやストレージ枯渇を気にする必要がありません。
* **独立した実行環境:** 毎回クリーンなコンテナが立ち上がるため、前回の実行によるメモリリークやゴミファイルの影響を受けません。

## 3. アプリケーションの更新・デプロイ手順

ローカルでコード（検索クエリの追加、プロンプトの調整など）を修正した後、以下の手順でAWS本番環境へ反映させます。
※ECSタスクは常に `latest` タグのイメージを参照する設定になっているため、**ECRへPush（上書き）するだけで更新が完了します。**

### Step 1: Dockerイメージの再ビルド

ローカル環境でキャッシュを使わずにクリーンビルドを行います。

```bash
docker build --no-cache -t seal-app .

```

### Step 2: AWS ECRへのログイン

AWS CLIを使用して、コンテナレジストリ（ECR）へのアップロード権限を取得します。

```bash
aws ecr get-login-password --region ap-northeast-1 | docker login --username AWS --password-stdin 390403878175.dkr.ecr.ap-northeast-1.amazonaws.com

```

> **確認:** `Login Succeeded` と表示されれば認証成功です。

### Step 3: イメージのタグ付け & プッシュ

ビルドしたイメージにECR用のタグを付け、AWSへアップロードします。

```bash
# タグ付け
docker tag seal-app:latest 390403878175.dkr.ecr.ap-northeast-1.amazonaws.com/seal-app:latest

# アップロード (Push)
docker push 390403878175.dkr.ecr.ap-northeast-1.amazonaws.com/seal-app:latest

```

✅ **デプロイ完了:**
次回のスケジュール（EventBridge）実行時から、自動的に新しいコードが使用されます。

## 4. 運用オペレーション

### 手動での即時実行 (強制実行・テスト)

コード更新後すぐに動作確認をしたい場合や、イレギュラーで即時巡回させたい場合は、AWSコンソールから手動実行します。

1. **AWSコンソール** > **ECS** > クラスター **`SealCluster`** を開く。
2. **「タスク」** タブ > **「新しいタスクの実行」** をクリック。
3. 以下の設定で実行:
* **起動タイプ**: `Fargate`
* **タスク定義**: `SealTask` (リビジョン: `latest` もしくは最新の番号)
* **タスク数**: `1`
* **ネットワーキング (⚠️超重要):**
* サブネット: リストから適当なパブリックサブネットを選択。
* パブリックIP: **`ENABLED` (有効)** ← ※ここが無効だとインターネット(YahooやWP)に接続できずタスクが落ちます。



4. **「タスクの実行」** をクリック。

### 📊 ログの確認方法

実行時のエラーログや、Geminiが抽出した件数などは CloudWatch で確認できます。

1. **AWSコンソール** > **CloudWatch** > **ロググループ** を開く。
2. `/ecs/SealTask` （または設定したロググループ名）を開き、最新のログストリームを確認します。

## 5. ローカル開発環境での実行

開発中に手元のPCで動作確認をするためのコマンドです。

```bash
# .envファイルを読み込んでコンテナを実行
docker run --env-file .env seal-app

```

### 必須環境変数 (.env / ECSタスク定義の環境変数)

* `GEMINI_API_KEY`: Gemini APIキー
* `WP_API_URL`: WordPress REST APIのエンドポイント (例: `https://www.seal-search.com/wp-json/wp/v2`)
* `WP_USER`: WordPress ユーザー名
* `WP_APP_PASSWORD`: WordPress アプリケーションパスワード
* `AWS_REGION`: `ap-northeast-1`
* `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`: ※ローカル実行時のみ必要。本番のECS環境ではコンテナに付与された「タスクロール」を使用するため設定不要です。
